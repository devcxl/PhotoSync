# 04: P4 BYOK AndroidKeyStore 密钥库与闭世界 EXIF 隐私清洗管线

**What to build:** 建设 P4 云端生成式能力的客户端安全与隐私底座：不引入已废弃的 `security-crypto`，直接基于 `AndroidKeyStore` AES-256-GCM（Keystore 自动生成随机 IV、不绑定锁屏/生物认证）实现 API Key 与自定义 Auth Header 加密存储，密文持久化于 `noBackupFilesDir` 以防云备份与 OEM D2D 迁移泄漏，并在 Keystore 损坏时自动清理损坏别名并引导重输；构建闭世界外发图像清洗管线（先读尺寸与 EXIF 方向 → 2 的幂降采样解码 → 旋正 → 精确缩放至长边 ≤2048 px → 重编码为 JPEG q90 → 校验零敏感元数据 → 随机无语义文件名，用完即删），彻底剥离 GPS、机身/镜头序列号、拍摄时间与嵌入式缩略图；落地网络安全策略守卫：公网端点 100% 强制 HTTPS、仅对经字面量与解析双重私有 IP 校验的自建局域网 ComfyUI 放开显式明文 HTTP，且对携带认证头的请求禁用跨源自动重定向并严禁日志泄露凭据。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 密钥库单测与真机验证通过：可加密存取多组 BYOK 凭据且密文落盘于 `noBackupFilesDir`；模拟 Keystore 密钥失效/损坏时优雅清除损坏密文并返回需重新配置状态而不崩溃。
- [ ] 隐私清洗单测验证通过：输入包含 GPS 坐标、相机机身与镜头序列号、拍摄时间及 IFD1 嵌入式缩略图的测试图片，清洗重编码后的输出文件长边 ≤2048 px、方向正向，且经元数据读取校验所有敏感 EXIF 字段与嵌入式缩略图均完全为空；临时文件在请求结束或异常时必定删除。
- [ ] 网络安全守卫单测验证通过：任何指向公网域名或公网 IP 的 `http://` 请求一律在发包前被拒绝；仅当用户显式开启局域网选项且目标通过字面量私有 IPv4（RFC1918 / `127.0.0.1`）与解析地址双重校验时允许明文 HTTP；携带认证头的请求关闭自动重定向且限制响应体大小 ≤32 MB。
- [ ] 审查与回归测试确认所有日志输出路径与异常消息不包含 API Key、Auth Header 或用户原始照片本地路径。
